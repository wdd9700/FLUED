# v3.4 位置编码与 Memory 确定性重跑

## 实验口径

- 小型完整 v3.4：约 37.3M FLUED + 4.8M 临时主干；
- 512 bytes，batch 8，seed 42；
- PyTorch 确定性算法，数据加载进程数为 0；
- 结构化字节查找表、局部 DiT segmentor、chunk-local interpreter、小 AR 头、硬发声门控全部开启；
- 3K 均匀边界预热后切换 L2 边际编码率；
- 5K memory 结果直接取同一 20K 训练轨迹的 `step_005000.pt`；
- 阈值扫描不更新权重，每个阈值重置相同随机种子与评估数据流。

## 位置编码结论

提示级绝对位置在结构化 byte lookup 输出后注入，同时保留 chunk 内局部 RoPE。该混合方案明显优于旧分层 RoPE；位置缩放 `0.03` 在本轮最平衡。仅使用提示级位置会丢失 chunk 内相对顺序，不能采用。

## Memory 结论

| 阶段 | 对照 | 重建准确率 | 补全准确率 | 困惑度 | 实际潜向量/字节 |
|---|---|---:|---:|---:|---:|
| 5K | memory | 88.80% | 13.75% | 35.72 | 0.719 |
| 5K | no-memory | 85.41% | 12.61% | 39.31 | 0.718 |
| 20K 默认阈值 | memory | 81.05% | 13.53% | 35.96 | 0.346 |
| 20K 默认阈值 | no-memory | 97.04% | 13.24% | 37.91 | 0.588 |

5K 证明 memory 分支不是天然有害；20K 证明它会逐渐形成低码率语义辅助，但精确重建路径发生长期退化。公平的同计算预算扫描显示，在约 `0.34-0.46 latent/byte` 的紧预算区间 memory 困惑度更低，在约 `0.59 latent/byte` 的较宽预算点则不占优。

因此下一步不是删除 memory，而是先校正 memory/readout 的归一化和残差尺度，再以相同实际潜向量预算比较。默认阈值单点不能作为 memory 消融结论。
