# FLUED v3.4 两组归因矩阵结果（2026-07-16）

## 1. 结论摘要

本轮完成两组长程矩阵和一个补充对照，共 140K + 20K 训练步：

1. 将边界课程总时长从 20K 放大到 40K，不能恢复动态阶段的重建能力；
2. 将过渡期从 1K 缩短到 500 步略有改善，但不能解决坍缩；
3. 主要故障不只在 Segmentor 切换。硬 emit 在 6K 切换前已经把实际 latent 容量压低，重建先行坍缩；
4. 动态边界完全接管后又出现第二次冲击，原始梯度长期出现百至万级尖峰；
5. memory 使用率权重 0.05 在当前单种子小模型上形成最佳系统折中：困惑度下降、实际 latent 更少、重建几乎持平；
6. 当前 memory 是无位置的集合式上下文。chunk 顺序置换本来就应当不改变注意力结果，不能用该干预否定 memory 语义；
7. 置零和跨样本替换会稳定恶化困惑度，说明模型确实利用了样本特定的 memory 内容；但更强 gate 监督并未增强这种因果依赖。

因此，下一步不能直接扩到 300M。应先拆开 `codec 对齐`、`emit 容量控制`、`边界执行` 和
`边界梯度信用` 四条课程，再决定 memory 是无序全局摘要还是带 byte anchor 的有序语义记忆。

## 4. Memory 使用率矩阵

### 4.1 与严格 no-memory 对照

| 实验 | 重建 | 补全 | 困惑度 | 实际 latent/byte | memory gate | memory 残差比 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| no-memory | 21.00% | 11.28% | 44.297 | 0.204 | 0 | 0 |
| memory，权重 0 | 18.28% | 11.33% | 45.173 | 0.131 | 0.163 | 0.045 |
| memory，权重 0.02 | 19.68% | 11.26% | 43.769 | 0.232 | 0.207 | 0.046 |
| memory，权重 0.05 | 20.74% | 11.41% | 43.488 | 0.191 | 0.233 | 0.051 |

相对 no-memory：

- 权重 0：困惑度恶化 0.876，重建下降 2.72 个百分点；
- 权重 0.02：困惑度改善 0.528，但 latent 成本增加 13.7%；
- 权重 0.05：困惑度改善 0.809，latent 成本降低 6.4%，重建仅下降 0.26 个百分点。

在当前单种子结果中，0.05 是唯一明确推进率失真前沿的候选。它仍需多种子和 2048/4096 长度
确认，不能直接上升为稳定架构结论。

### 4.2 修复后的 memory 内容干预

最初干预工具没有恢复检查点中的动态边界运行态，错误地使用了 `uniform_budget`；旧的 41.x
困惑度干预结果全部作废。工具已恢复 `runtime_boundary_state` 后重跑。

下表为相对 normal 的困惑度变化：

| 实验 | memory 置零 | 样本内 chunk 换序 | 跨样本 memory |
| --- | ---: | ---: | ---: |
| 权重 0 | +0.747 | -0.006 | +0.837 |
| 权重 0.02 | +0.509 | +0.027 | +0.536 |
| 权重 0.05 | +0.305 | +0.031 | +0.256 |

解释边界：

1. 置零和跨样本替换稳定恶化，证明模型使用了样本特定的 memory 内容；
2. 当前 memory cross-attention 没有位置编码。对键值对共同换序，注意力在数学上是置换不变的，
   所以 chunk 换序无影响是结构预期，不是“memory 没有语义”的证据；
3. 权重越高，gate 从 0.163 升到 0.233，但 memory 残差只从 4.5% 升到 5.1%，且置零损失增量
   反而降低。当前监督更像在校准门控和整体优化轨迹，不等价于增强有效 memory 依赖。

## 5. 已解决与未解决

### 已有足够答案

- 40K 不是解决方案，当前故障不是简单欠训练；
- 500 或 1K 过渡都不能修复联合非平稳；
- hard emit 与动态边界是两个连续发生、需要分别处理的问题；
- memory 并非完全无用，0.05 权重值得进入下一轮；
- 样本内 memory 换序不是有效的语义检验，因为当前 memory 是无位置集合。

### 仍需架构决策

1. **训练课程是否拆成四条。** 推荐拆为：固定容量 codec 对齐、emit 容量课程、边界前向课程、
   边界主任务梯度课程。当前一个总开关同时改变表示容量和梯度路径，已经被实验证伪。
2. **memory 是集合还是序列。** 保持无位置集合，适合实体和领域上下文；加入 byte-anchor 相对位置，
   才能表达顺序与局部对应。两者是功能取向，不应通过错误的 shuffle 指标替代决策。
3. **监督 gate 还是实际贡献。** 当前 gate 达标不代表 memory 因果贡献增强。可保留 0.05 作为弱约束，
   但不建议继续增大；若要求强语义记忆，应改为监督有效残差或反事实移除收益。
4. **共享逆 decoder 如何解耦。** 冻结 readout 实验已证明函数形态可拟合；下一轮应选择 decoder
   预热、交替更新或梯度缩放，而不是继续全量同步反向传播。

## 6. 建议的下一步

在用户确认上述架构分岔前，不启动 300M。无需再确认即可执行的工程准备是：

1. 将 boundary 前向混合系数与主任务梯度桥系数拆成独立时间表；
2. emit 在 codec 预热期固定 fallback + 固定 extra 容量，之后再开放硬发声；
3. 保留 memory 权重 0.05 作为候选默认，但把 no-memory 继续作为每轮严格对照；
4. 增加“跨样本替换、局部 memory 删除、实体检索”探针，删除无意义的整体 chunk 换序判据；
5. 完成 5K 定位后再做 20K、多种子、2048/4096 长度验证。
